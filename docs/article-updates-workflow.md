# 既存記事の更新登録

正本は `portal/article-updates.json`。RSS の公開日、AtomPub の updated、ファイル変更日時から自動登録しない。
新着記事、カテゴリー変更、機械的な再保存を医学的改訂として扱わない。

1. 記事の改訂を既存の承認・公開手順で完了する。記事本文・投稿日はこの仕組みから変更しない。
2. 未ログインの公開URLで改訂箇所を確認し、改訂前との差分・公開確認日時・保存した証跡を記録する。下書き画面やローカル成果物だけでは登録しない。
3. 台帳へ `id`（改訂ごとに一意）、`date`（実際の改訂公開日 YYYY-MM-DD）、`title`、`summary`（読者に伝える具体的変更点）、`url`（公開記事）、`public_verified: true`、`evidence`（証跡の参照先と確認内容）を追加する。医学的な変更でなければ「動画を追加」など実際の変更を書く。証拠のない日付は推測しない。
4. `python -X utf8 build_portal.py` と `python -m pytest tests -q -p no:cacheprovider`、`python tests/browser_article_updates.py` を実行。総合トップ・ブログ表示部品・一覧は同じ台帳から生成される。直近5件＋過去分の折り畳みを確認する。
5. 完成差分と証跡を確認し、README の公開承認手順に従って変更ファイルのみコミット・公開する。公開対象に生台帳・証跡は含まれない。公開後は両トップと記事リンクを確認する。

## 初回導入

先にポータルを公開し `/article-updates.html`、`/article-updates-widget.js`、`/article-updates.css` が200になることを確認する。
はてな「デザイン→ヘッダ→ブログタイトル下」の現行HTMLを**管理画面からそのままバックアップ**する。
`docs/hatena-recent-updates-snippet.html` を `h2.ich-latest-title`（新着記事）の直前へ追加する。末尾への追加は新着見出しと一覧を分断するため行わない。既存ナビ・検索・自己紹介・カテゴリーは保持する。
保存は公開操作なので、完成版の公開承認後に実施する。トップ `/` にのみ部品を表示し、記事・アーカイブには挿入しない。
JavaScript無効時は更新一覧へのリンクのみ表示される。外部スクリプトが失敗した場合も同リンクを残す。
二回目以降は台帳を更新してポータルを公開するだけで、ブログも同じ部品を取得する。はてなヘッダーの貼り直しは不要。
公開後にスマホ320/390px、PC、キーボード、検索・保存機能、記事・アーカイブで確認する。

## 差し戻し

はてなは保存したヘッダー全文へ戻す（他作業があれば差分を確認し今回のBEGIN〜ENDだけ除去）。
ポータルは今回の公開コミットだけをrevertして再配信する。記事本文や投稿日は変更しない。
未コミットの差し戻しはバックアップの各ファイルを照合してから復元し、新規ファイルだけ除去する。
